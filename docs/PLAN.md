# iPhone SpecTest — 企画・開発計画

> iPhone のスペック表示と性能ベンチマークを行う **Web アプリ**の計画書。
> Safari で開くだけで使え、App Store 審査なしで公開できることを重視する。

---

## 1. コンセプト

「iPhone を Safari で開くと、**この端末のスペック**と**実際の性能スコア**がその場でわかる」Web アプリ。

- インストール不要（URL を開くだけ）。PWA 対応でホーム画面追加も可能。
- 計測はすべて端末内（ブラウザ内）で完結。個人情報は送信しない。
- **iPhone（iOS Safari）で回す前提**。UI・スコア基準・機種DB は iPhone 最適化に振り切る。
  Android / PC は「一応動く」程度で、フォールバックには労力をかけない。

### 中心となる2機能
1. **スペック表示** — 端末情報を取得・推定して見やすく一覧表示。
2. **性能ベンチマーク** — CPU / GPU / メモリ / 描画性能を実測してスコア化し、他機種と比較。

---

## 2. なぜ Web（PWA）か

| 観点 | Web(PWA) | ネイティブ(Swift) |
|------|----------|-------------------|
| 公開の速さ | URL 公開だけ・審査なし | App Store 審査あり |
| 必要な環境 | エディタのみ | Mac + Xcode + Developer登録(¥/年) |
| 更新 | デプロイ即反映 | 審査待ち |
| ハード情報の深さ | △ 制限あり | ◎ 深くアクセス可 |
| 到達範囲 | 全デバイスのブラウザ | iOS のみ |

→ **まず Web で出す**。将来ネイティブが必要になれば同じロジックを移植可能。

---

## 3. Web で取れる情報と制約（重要）

iOS Safari はプライバシー保護のため多くの API を制限している。**「取れる」「推定する」「DB照合する」**の3層で設計する。

### 3-1. ブラウザ API で直接取れるも
- OS バージョン / ブラウザ：`navigator.userAgent`
- 画面：`screen.width/height`, `window.devicePixelRatio`（→ 論理/物理解像度）, 色深度
- CPU 論理コア数：`navigator.hardwareConcurrency`（Safari は上限が丸められる場合あり）
- タッチ点数：`navigator.maxTouchPoints`
- ストレージ空き見積り：`navigator.storage.estimate()`
- GPU 名：WebGL の `WEBGL_debug_renderer_info`（近年の Safari では "Apple GPU" 等にマスクされる）
- 対応機能：WebGL/WebGPU、WASM、各種センサー可否
- 言語・タイムゾーン：`navigator.language`, `Intl`

### 3-2. Safari で **取れない/制限が強い**もの（要注意）
- **正確な機種名**（iPhone 15 Pro 等）：UA では区別不可 → 後述の推定＋DB照合で対応
- バッテリー残量（Battery API 非対応）
- 端末メモリ量（`navigator.deviceMemory` 非対応）
- 詳細なネットワーク種別（Network Information API 制限）
- モーション/方位センサー：iOS では**ユーザー許可**が必須（`DeviceMotionEvent.requestPermission`）

### 3-3. 機種推定のアプローチ
`画面解像度 × devicePixelRatio × maxTouchPoints × WebGL情報 × ベンチスコア` を
**機種スペックDB（内蔵JSON）**と照合し、候補機種を絞り込んで提示する
（「iPhone 14 / 14 Pro のいずれか」のように候補表示も許容）。

## 4. ベンチマーク設計

すべて端末内で完結する JS/WASM/WebGL 計測。1〜2秒ずつ実行し合成スコア化。

| テスト | 内容 | 使う技術 |
|--------|------|----------|
| CPU（シングル） | 素数計算・ソート・数値演算ループ | JS / WASM |
| CPU（マルチ） | Web Workers で並列実行 | Web Workers |
| メモリ帯域 | 大配列のコピー/走査速度 | TypedArray |
| GPU/描画 | 大量オブジェクト描画の FPS 計測 | WebGL(将来 WebGPU) |
| DOM/UI | レイアウト・再描画のフレーム時間 | requestAnimationFrame |

- 各スコアを正規化 → **総合スコア**を算出。
- 基準端末（例：iPhone 12 = 1000）でスケーリングし直感的な数字に。
- 計測は複数回の中央値を採用してブレを抑制。

---

## 5. 技術スタック（案）

- **フレームワーク**：React + TypeScript + Vite（軽量・高速・PWA化容易）
- **スタイル**：Tailwind CSS
- **状態**：軽量なので React 標準（Context）で十分
- **並列計測**：Web Workers（Comlink で簡潔化）
- **PWA**：vite-plugin-pwa（オフライン対応・ホーム画面追加）
- **グラフ**：スコア比較の可視化（軽量チャート）
- **ホスティング**：Vercel / Netlify / GitHub Pages（いずれも無料枠で可）
- **機種DB**：`src/data/devices.json`（メンテしやすい静的データ）

---

## 6. 画面構成（MVP）

1. **トップ**：この端末の要約（推定機種・OS・解像度）＋「ベンチ開始」ボタン
2. **スペック詳細**：取得できた情報を項目ごとに一覧。取れない項目は「Web制限」と明示。
3. **ベンチ実行中**：各テストの進捗表示。
4. **結果**：総合スコア＋項目別スコア。他機種とのバー比較。
5. **共有**：結果を画像/リンクで共有（任意・送信は明示同意）。

## 7. 開発ロードマップ

### フェーズ0：土台（0.5日）
- Vite + React + TS + Tailwind 雛形、リポジトリ整備、デプロイ疎通（Hello World 公開）。

### フェーズ1：スペック表示 MVP（1〜2日）
- ブラウザ API から取れる情報を収集するモジュール `useDeviceInfo`。
- スペック一覧 UI。取れない項目のフォールバック表示。

### フェーズ2：ベンチマーク（2〜3日）
- CPU/メモリ/描画テストを実装 → スコア化 → 結果画面。
- Web Workers でマルチコア計測。

### フェーズ3：機種推定＋比較DB（2日）
- `devices.json` を用意し、指紋情報＋スコアで機種推定。
- 他機種とのスコア比較 UI。

### フェーズ4：仕上げ（1〜2日）
- PWA 化、結果共有、i18n（日本語/英語）、デザイン調整、計測精度チューニング。

## 8. 技術的な注意点

- **計測のブレ**：発熱・省電力・他アプリ影響でスコアが変動 → 複数回中央値＋「参考値」と明記。
- **プライバシー**：計測は端末内完結、送信するのは共有時のみ・明示同意。プライバシー方針を1画面用意。
- **Safari 差分**：iOS の Safari 固有制限を前提に、機能検出（feature detection）で分岐。
- **精度の限界を正直に見せる**：取れない情報を隠さず「Webの制限」と表示することが信頼につながる。
